## Frozen draft schema v1

`content.create_draft` accepts exactly `schema_version: 1`, `organization_id`, `project_id`, `card_kind` (`project_task` or `engagement_work_item`), `card_id`, `request_id`, `previous_version_id` (UUID or null), `title` (1–240 characters), and `body` (1–100000 characters). UUIDs are explicit. Text is supplied, never generated by this adapter. No actor, service-role credentials, approval, publication, or cost input is accepted.

Invoke `createSuppliedDraft(callerAuthenticatedClient, input)`. The transaction checks current project/card write authority, rejects archived projects and stale document versions, then calls canonical `save_work_content`. Retry the unchanged request and payload after an unknown response. Current authority is checked on retries too. No claim impersonation is supported.

Receipt: `schema_version`, `organization_id`, `project_id`, `card_kind`, `card_id`, `request_id`, `asset_kind: content`, `document_id`, `version_id`, `version_number`, `state: draft`. This is the existing Work content asset type, NOT an `artifact_versions` approval record. Reopen with existing `work_content_version` and Work-card asset controls. Document identity and exact version identity are distinct fields. No second artifact store is introduced.
